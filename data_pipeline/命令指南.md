# 数据管道系统 - 命令使用指南

## 📚 系统简介

数据管道系统负责处理学术文献，构建向量数据库和知识图谱，为 Agentic RAG 系统提供数据支持。

**核心流程**：
```
文档加载 → 智能分块 → 元数据增强 → 向量化 → 存储到 Milvus
                ↓
            知识图谱提取 → 存储到 Neo4j
```

**最新改进**（2025-01-09）：
- ✅ **增强分块策略**：数据密集型章节使用更大的分块（1200 字符）
- ✅ **语义元数据标注**：自动标注数值数据、方法描述等
- ✅ **优化检索阈值**：提高相似度阈值（0.15 → 0.30）

## 💻 主要命令

### 命令一：完整数据管道（串行）

构建完整的向量数据库和知识图谱：

```bash
python run_pipeline.py
```

**流程说明**：
1. ✅ 检查系统环境和配置
2. 📄 加载学术文档
3. ✂️ 智能分层分块
4. 🏷️ **增强元数据标注**（新增）
5. 🔢 生成嵌入向量
6. 💾 存储到 Milvus
7. 🔗 构建知识图谱（可选）

**参数选项**：
```bash
# 基础运行（使用默认配置 仅向量数据库）
python run_pipeline.py

# 加知识图谱构建
python run_pipeline.py --kg

# 强制重建（删除现有数据）
python run_pipeline.py --force-rebuild

# 指定文档目录
python run_pipeline.py --docs-path /path/to/your/documents

# 详细输出
python run_pipeline.py --verbose
```

**完整示例**：
```bash
# 标准运行（推荐 仅向量数据库）
python run_pipeline.py

# 构建向量数据库+KG
python run_pipeline.py --kg

# 完全重建所有数据
python run_pipeline.py --kg --force-rebuild --verbose
```

### 命令二：并行数据管道（推荐）

使用多线程加速处理：

```bash
python run_pipeline_parallel.py
```

**优势**：
- ⚡ 速度提升 3-5 倍
- 🔄 自动批处理
- 💾 增量保存（防止中断丢失）

**参数选项**：
```bash
# 基础并行运行
python run_pipeline_parallel.py

# 自定义工作线程数
python run_pipeline_parallel.py --workers 8

# 自定义批次大小
python run_pipeline_parallel.py --batch-size 100

# 加知识图谱
python run_pipeline_parallel.py --kg

# 完整配置
python run_pipeline_parallel.py \
    --workers 10 \
    --batch-size 50 \
    --force-rebuild \
    --verbose
```

python run_pipeline_parallel.py \
    --kg \
    --force-rebuild \
    --workers 50 \
    --batch-size 500 \
    --verbose

**性能对比**：
| 文档数 | 串行 | 并行（10 workers） | 提速 |
|--------|------|-------------------|------|
| 100 篇 | ~30 分钟 | ~8 分钟 | 3.8x |
| 500 篇 | ~2.5 小时 | ~35 分钟 | 4.3x |
| 1000 篇 | ~5 小时 | ~1.2 小时 | 4.2x |

## 📊 数据管道流程详解

### 阶段 1: 文档加载

```
[文档目录] → DocumentLoader → [文档列表]
```

**支持格式**：
- Markdown (.md)
- 自动检测编码（UTF-8, GB2312, GBK）

**输出**：
```python
{
    'content': '文档内容...',
    'metadata': {
        'filename': 'paper.md',
        'source': '/path/to/paper.md',
        'encoding': 'utf-8'
    }
}
```

### 阶段 2: 智能分块

```
[文档] → PhotovoltaicTextSplitter → [分块列表]
```

**策略**：
1. 识别章节类型（abstract, introduction, results 等）
2. 根据章节类型使用不同的分块大小
3. **新增**：数据密集型章节使用更大分块（1200 字符）

**章节分块配置**：
| 章节类型 | 分块大小 | 重叠 | 说明 |
|---------|---------|------|------|
| Results | 1200 | 300 | 保留完整数值表格 |
| Performance | 1200 | 300 | 保留数值关联 |
| Experimental | 1200 | 300 | 保留完整方法 |
| Introduction | 1000 | 250 | 保留上下文 |
| Abstract | 800 | 200 | 完整摘要 |
| Conclusion | 600 | 100 | 完整结论 |

### 阶段 2.5: 元数据增强（新增）

```
[分块] → ChunkMetadataEnricher → [增强分块]
```

**添加的元数据**：
```python
{
    'has_numerical_data': True,        # 是否包含数值
    'has_methods': False,              # 是否包含方法描述
    'has_comparisons': False,          # 是否包含对比
    'numerical_values': ['98%', '99%'], # 提取的数值
    'key_metrics': ['PLQY', 'PCE'],    # 关键指标
    'content_density': 'high'          # 内容密度
}
```

**用途**：
- 🎯 帮助 RAG 系统识别高价值分块
- 🔍 支持基于内容类型的过滤
- 📊 提高数值问题的检索精度

### 阶段 3: 向量化

```
[分块] → EmbeddingGenerator → [向量]
```

**模型**: `text-embedding-3-small` (1536 维)
**批处理**: 1000 个/批次
**性能**: ~100 个分块/秒

### 阶段 4: 存储到 Milvus

```
[向量 + 元数据] → VectorManager → [Milvus 数据库]
```

**索引类型**: IVF_FLAT
**距离度量**: COSINE
**集合**: academic_papers

### 阶段 5: 知识图谱构建（可选）

```
[分块] → OptoelectronicKGExtractor → [实体和关系]
              ↓
         Neo4jManager → [知识图谱]
```

**提取内容**：
- 实体：材料、器件、指标、工艺等
- 关系：HAS_PROPERTY, FABRICATED_BY, MEASURES 等
- 属性：数值、单位、条件等

## 🔧 常见操作

python run_pipeline_parallel.py --skip-kg --workers 10

## 📈 性能优化建议

### 1. 并行处理

**推荐配置**：
```bash
# 根据 CPU 核心数调整
# 8 核 CPU → 6-8 workers
# 16 核 CPU → 10-14 workers
python run_pipeline_parallel.py --workers 10 --batch-size 50
```

### 2. 批次大小

| 批次大小 | 内存使用 | 速度 | 推荐场景 |
|---------|---------|------|----------|
| 20 | 低 | 慢 | 内存受限 |
| 50 | 中 | 中 | 标准配置 |
| 100 | 高 | 快 | 高性能服务器 |

### 3. 分块策略调整

如果遇到检索不准确，可以调整分块配置：

```python
# 编辑 core/photovoltaic_text_splitter.py
self.section_chunk_configs = {
    'results': {
        'chunk_size': 1500,    # 进一步增大
        'chunk_overlap': 400   # 增加重叠
    }
}
```

### 4. 向量化加速

```python
# 编辑 config/config.py
embedding_batch_size = 2000  # 增大批次（需要更多内存）
```

## 🐛 故障排除

### 问题 1: Milvus 连接失败

```bash
# 检查 Milvus 服务
docker ps | grep milvus

# 如果未运行，启动服务
cd config
docker-compose up -d

# 检查日志
docker logs milvus-standalone

# 验证连接
python -c "from pymilvus import connections; connections.connect(host='localhost', port='19531'); print('OK')"
```

### 问题 2: Neo4j 连接失败

```bash
# 检查 Neo4j 服务
docker ps | grep neo4j

# 测试连接
python -c "
from neo4j import GraphDatabase
driver = GraphDatabase.driver('bolt://localhost:7688', auth=('neo4j', 'password'))
driver.verify_connectivity()
print('OK')
"
```

### 问题 3: 内存不足

```bash
# 减小批次大小
python run_pipeline_parallel.py --batch-size 20 --workers 4

# 或使用串行处理
python run_pipeline.py
```

### 问题 4: OpenAI API 限流

```bash
# 减小并发数
python run_pipeline_parallel.py --workers 2 --batch-size 20

# 或增加重试间隔（编辑代码）
```

### 问题 5: 分块质量问题

```bash
# 查看分块统计
python run_pipeline.py --verbose | grep "分块统计"

# 检查具体分块
python -c "
from core import PhotovoltaicTextSplitter, DocumentLoader
loader = DocumentLoader('path/to/docs')
splitter = PhotovoltaicTextSplitter()
docs = loader.load_all_documents()
chunks = splitter.split_documents(docs)
for chunk in chunks[:5]:
    print('---')
    print(chunk['content'][:200])
    print(chunk['metadata'])
"
```
