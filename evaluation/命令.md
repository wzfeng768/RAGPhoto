## 5. 增量评估与断点续传 ⭐新功能

**增量评估** (默认启用):
- 每完成一个问题就立即保存结果
- 中途失败不会丢失已完成的工作
- 实时查看评估进度

**断点续传**:
- 从上次中断的地方继续评估
- 跳过已完成的问题

```bash
# 标准评估（增量保存）
python evaluate_rag.py --dataset computational --num_questions 50

# 如果中途中断，使用 --resume 继续
python evaluate_rag.py --dataset computational --num_questions 50 --resume

# 使用批量模式（关闭增量保存）
python evaluate_rag.py --dataset computational --num_questions 10 --no-incremental

# 如果 RAGAS 评估不稳定（超时/错误），跳过 RAGAS 只使用事实检查 ⚠️推荐
python evaluate_rag.py --dataset computational --num_questions 10 --skip-ragas
```

**增量评估的优势**:
- ✅ 每题完成后立即保存，中途失败不丢失进度
- ✅ 实时查看结果文件，了解评估进展
- ✅ 支持断点续传（--resume）
- ✅ 自动重试NaN指标（最多3次）
- ✅ 详细的日志输出

**使用场景**:
```bash
# 场景1：开始一个大型评估
python evaluate_rag.py --dataset all --num_questions 100

# 场景2：中途网络中断，使用 --resume 继续
python evaluate_rag.py --dataset all --num_questions 100 --resume

# 场景3：查看进度
cat results/all/direct_llm/results.json | jq '.metadata.num_questions_completed'
```

**使用场景**：
- 已经运行过评估并生成了答案
- 想要重新计算评估指标（比如修改了评估代码）
- 节省时间和API成本

```bash
# 重新评估单个结果
python re_evaluate.py --dataset computational --mode direct_llm

# 重新评估特定数据集的所有模式
python re_evaluate.py --dataset all --mode agentic_no_kg
python re_evaluate.py --dataset all --mode agentic_with_kg
python re_evaluate.py --dataset all --mode direct_llm

# 只重新计算RAGAS指标（跳过事实检查）
python re_evaluate.py --dataset all --mode agentic_no_kg --skip-fact

# 只重新计算事实正确性指标（跳过RAGAS）
python re_evaluate.py --dataset all --mode agentic_no_kg --skip-ragas

# 批量重新评估所有已有结果
./re_evaluate_all.sh
```

**优势**：
- ✅ 不需要重新调用LLM生成答案
- ✅ 大幅节省时间（从小时级降到分钟级）
- ✅ 节省API成本
- ✅ 可以选择性地只重新计算某些指标

## 11. 注意事项

1. **避免重复评估**: `all` 数据集包含了所有分类的题目，不要同时评估 `all` 和单个分类然后对比
2. **结果位置**: 结果保存在 `results/{数据集名称}/{模式}/results.json`
3. **时间估计**: 单题约需10-30秒（Agentic模式），Direct LLM较快
4. **推荐用法**: 
   - 快速测试: `--dataset computational --num_questions 5`
   - 完整评估: `--dataset computational --num_questions all --mode all`
   - 大规模测试: `--dataset all --num_questions 100`
5. **模型配置**: 可通过命令行参数自定义答案生成和评估模型（见第8节）
6. **智能数值评估** ⭐新特性: 系统能识别语义等价的数值表达
   - 例如：标准答案"98%-99%"，回答"接近100%"会被认为正确
   - 支持中英文近似表达（"约"、"接近"、"approximately"、"around"等）
   - 详见[使用指南.md](使用指南.md#评估指标说明)

### ⚠️ 常见问题排查

| 问题 | 原因 | 解决方法 |
|------|------|----------|
| 某类别在图中为空/高度为0 | `summary_data.json` 中该类别 `total_qas=0` | 重新运行：`python visualize_results.py --dir results/<模型>/<类别>` |
| 某模型未出现在图中 | `MODEL_COLORS` 未定义该模型颜色 | 在 `compare_models.py` 的 `MODEL_COLORS` 字典中补充 |
| `--common-qa` 找不到QA | 未运行 `compare_reports.py` 或报告缺失 | 先运行 `python compare_reports.py` |
| `model_comparison` 被误当模型 | 目录过滤缺失 | 已修复，`NON_MODEL_DIRS` 已包含 `model_comparison` |
